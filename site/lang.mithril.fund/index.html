01 · The language

A source form with a visible contract.

Mithril is an ontology-based language for describing programs and their meaning. A source document identifies the vocabulary it uses; the compiler projects it into RDF, validates its declared shape, and emits a typed action artifact.

Source files.mith · .mithril

Both suffixes are accepted aliases.

Readable surfaceMithril Form

Tagged S-expressions with keyword fields, nested forms, and vectors.

Convertible representationsMithril Form ↔ JSON-LD 1.1

02 · Source grammar

Forms are read, checked, then compiled.

The grammar below describes the canonical reader-level shape. Token decoding follows the ClojureScript reader; each form tag defines its own allowed fields, argument positions, types, and vocabulary. The reader accepts one top-level form and treats it as data; it does not run Clojure, resolve namespaces, or invoke host functions.

Reader rules

  • A source file contains exactly one tagged top-level form.
  • Fields are keyword/value pairs; duplicate fields are rejected.
  • Vectors preserve ordered values. Nested forms must use admitted tags.
  • Strings, integers, booleans, nil, vectors, and nested tags are the supported general values.
  • Positional forms such as RDF constructors are specified by their own tag contract.
  • JSON-LD is a distinct, mutually convertible representation with its own JSON-LD syntax and pinned context.
Download the EBNF reader grammar ↓ 
form-source  = trivia, tagged-form, trivia ;
tagged-form  = "(", symbol, { trivia, argument }, trivia, ")" ;
argument     = keyword, trivia, value | value ;
value        = string | integer | boolean | nil | vector | tagged-form ;
vector       = "[", [ value, { trivia, value } ], "]" ;

symbol       = reader-symbol-token ;
keyword      = reader-keyword-token ;
integer      = reader-integer-token ;
boolean      = "true" | "false" ;
nil          = "nil" ;
string       = '"', { character | escape }, '"' ;
trivia       = { whitespace | comma | comment } ;

This EBNF describes the canonical source spelling; lexical tokens follow cljs.reader. It is not a promise that every tag accepts every syntactically valid value. Type and field rules are defined by the selected Mithril vocabulary and compiler profile. Full EBNF.

03 · Execution model

Mithril sits above Kotoba and Amu.

The execution foundation is Kotoba Lang’s typed runtime and Amu compiler/backend. Amu’s self-hosting compiler path belongs to the Kotoba/Amu toolchain; Mithril’s own compiler front end remains implemented with CLJK/CLJS host primitives.

  1. 01Read inert sourceMithril Form or JSON-LD
  2. 02Check meaningCanonical RDF and closed vocabulary admission
  3. 03Build typed actionOaK transaction and Execution IR
  4. 04Execute through KotobaOsaho semantics → Amu backend

Boundary: Amu self-hosting does not mean the Mithril compiler itself is self-hosted. Mithril’s declared .mith language kernel describes and admits its orchestration; host readers, RDF adapters, and compiler primitives remain explicit implementation components.
