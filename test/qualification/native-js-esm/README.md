# Native multi-file ESM linking

`mithril/native-js-esm-package` is a separate checked profile. It emits independent native ESM files instead of wrapping imports in package factories. The JavaScript engine owns linking, namespace identity, live bindings, native temporal dead zones and cycle evaluation. Existing NativeJsPackage remains acyclic and its previous artifacts and admission rules are retained.

The manifest has name/imports/modules/reexports. Each module has name/source/dependencies/links: ordered unique dependencies include named links and can include side-effect-only imports; each link has import/module/export. Local `.mith` basenames, source identity, exact bounded source/capability sets, link membership, reachability and every leaf are admitted before emission. Private/default reexport aliases must also resolve to a real binding; originless alias cycles refuse. Native root `export *` excludes default, merges repeated paths to the same binding, and suppresses distinct binding origins with a shared name. Named default imports and explicit reexports retain native behavior.

Module functions emit real function declarations, including native hoisting and original function names. Module lexical bindings retain original declaration names and let/const semantics. Direct exported local/function/linked-import aliases use actual ESM export aliases; computed export values initialize once. Native self bindings that would shadow an explicit module import/function reference refuse, as do reserved or conflicting module declaration names. Source parameter/local renaming still uses the existing checked emitter; no universal diagnostic-text equivalence is claimed. Host capabilities use a shared pure global-object adapter, initialized before a source back edge can call a hoisted function using a capability. Individual host properties remain read at the source operation, not at declaration enumeration. This is a native host profile, not guest sandbox/provider authorization.

Compile `bin/mithril-native-esm.cljk <package.mith> --target js|js-browser --output-directory <new-directory>` with the pinned offline source engine. The directory must not exist. The CLI refuses symlink/nonregular/oversized leaf sources, completes admission before its first output, creates files exclusively, and cleans up only the directory it created if a write fails. No JavaScript parser, TypeScript compiler, evaluated source, source import, arbitrary path or runtime cycle surrogate is used by the compiler.

[CosmoKit ESM manifest](../../../examples/native-js-cosmokit-esm.mith) includes all six complete leaves and a checked native index expressing their forty live aliases in original root order. [Cordis leaves ESM manifest](../../../examples/native-js-cordis-leaves-esm.mith) includes the same index plus complete original utils/logger/reflect sources, ten modules and fifty-seven public names. Source dependencies go through the entire CosmoKit index, so importing one symbol still evaluates all original side-effect modules. These are complete dependency leaves; the four-file core SCC is not yet ported.

Eighteen runtime groups compare manually authored complete native JS reference graphs: cyclic function hoisting, mutable exports/reexport aliases, snapshots, default arguments, genuine native functions/classes, module namespace descriptors and strict mutation failure, single initialization, ordered side-effect imports and reversed roots, exact tested native TDZ names for value/class imports, thrown initialization failures, host getter timing, host use by a declaration during a back edge, native star/default/ambiguity behavior and both actual CLI imports. A failing regression was retained externally: a hoisted function accessed the host adapter before initialization; moving the pure adapter import before source dependencies fixed it.

Both actual js/js-browser CLIs compile full CosmoKit and the ten-module dependency leaves. Original CosmoKit controls pass fifteen groups per target, including Buffer/browser branches and initialization getter order in Node VM realms. Complete reflect controls pass forty-four groups per target with genuinely linked compiled dependencies. Existing factory-mode reflect tests still run independently. Owner/event observation fixtures are not real Fiber/Events integration; js-browser runs in Node, not a browser. New-profile logger is compiled and initialized, while complete logger behavioral controls remain the independently retained factory controls. No complete core runtime equivalence is established here.

Full native source suite: 46 tests / 174 assertions, including thirty-seven admission refusals and five CLI output/source refusals for this profile. Existing package controls retain forty exports, fifteen groups per target, seven frozen leaf artifacts and cyclic refusal. Existing CosmoKit declarations retain 446 type nodes, strict ten positive/twelve negative consumer groups per target under TSC6.0.3 with no skipLibCheck. Those declaration controls cover the existing package profile, not new multi-file declarations or Cordis public types.
