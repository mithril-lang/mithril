# Native source prerequisites for Cordis logger

The pinned original Cordis logger uses class static initialization blocks, variadic lexical arrows, native integer hashing and a formatter closure that refers to a later class declaration. This change supplies those checked source semantics before porting the complete logger. [The executable Mithril control module](../../../examples/native-js-logger-prerequisites.mith) exercises all four; it is a syntax/semantics control, not a replacement logger implementation.

NativeClass members can contain an exact `kind: "static-block", body` node. It emits an actual native static block in the original member sequence. No key, static flag, parameters or arbitrary source is accepted. Block bodies lower directly in effect mode, with no synthetic return or helper function. Native class evaluation supplies computed-key-before-initializer order, one-time ordered static effects, block-local lexical scope, home-object super, class this, new.target undefined and abrupt completion. Static blocks and lexical arrows within them cannot read arguments or call super(); nested normal functions regain their own contexts and cannot inherit super.

NativeLambda now accepts optional rest (nil or a checked distinct identifier) and default parameters. Existing string and `{array: [...]}` patterns remain; a name pattern may use `{name: ...}`, and name/array patterns may contain a default checked expression. Parameters, rest and default expressions share the arrow's checked parameter scope and retain lexical this/arguments/new.target/super context. Native parameter syntax preserves length, nonconstructibility, fresh rest arrays, iterator closing and default parameter TDZ. Missing rest and explicit nil retain the old bytes. No async arrow or object/nested destructuring surface is claimed.

HostBinary admits native `<<`, `>>`, `>>>`, `&`, `|`, `^` and `>`; HostUnary admits `~`. Emission uses the actual operators, retaining native ToNumeric, Number/BigInt distinctions, mixed-type and Symbol exceptions, operand/coercion order, shift masking and signed/unsigned behavior. Compound property assignment operators are not admitted. The source logger's plain local hash assignment can combine LocalSet with the actual bitwise expression; no numeric approximation is substituted.

NativeJsModule accepts optional exact boolean `lexical_bindings`. True checks every initializer against the complete declared binding scope and preallocates fresh identifiers before lowering initializer bodies, while emitting real const/let declarations in source order. Forward and mutually captured closures work; eager reads, calls through early closures and writes before initialization throw native ReferenceError. Mutability is checked against each declared binding. Unknown bindings, duplicate/conflicting names and immutable writes refuse. Omitted/false retain legacy admission and allocation order. This represents one module's lexical scope and is not ESM cyclic linking or a claim of whole runtime SCC support.

The actual js/js-browser CLI outputs pass 34 paired runtime groups, with four additional isolated-VM module-TDZ/closure groups (38 total). Controls compare native JavaScript reference syntax: class computed/static/instance order, lexical class capture and super setter receiver, block-local closure, early block throw, arrow rest/default/destructuring/lexical contexts and construction, forward formatter/class capture, and the native bitwise/relational operator corpus including Symbol, non-finite Number and BigInt. Separate checks preserve operand evaluation/coercion order and abrupt short circuit. Module controls cover deferred forward lookup, eager read/call/assignment TDZ, mutual closure identity and mutable captured state. The backend does not execute reference code or source strings; references are test-only.

Source suite: 34 tests / 140 assertions, including 26 malformed/name/scope/operator/budget refusals here and old-byte controls for nil rest/name patterns/false lexical mode. Retained full utils comparison, CosmoKit package (40 exports, 15 runtime groups per actual target, seven frozen leaf artifacts) and strict declarations (446 nodes; 10 positive / 12 negative groups per target; no skipLibCheck) remain passing.

Operator-authored, with zero new System One inference requests, repairs or model adoption. Previous sealed model trials stay unchanged. Node/VM evidence only; the complete original logger runtime source, public class/interface/namespace/module-augmentation declarations, five-file Cordis runtime SCC, service/index, Schemastery, full Harness APIs/plugins/profiles/Session and browser/native/Q9 parity remain required. Complete utils is already published; the next runtime source dependency is logger. Organization Harness destination remains unresolved, but independent source/compiler work continues.
