# Explicit mutable module function bindings

Functions opt into assignment with boolean `mutable: true`; `FunctionSet` requires that exact module function and an unshadowed target. Unknown, immutable, imported, lexical-local, parameter, catch/loop, native named self and malformed targets refuse. Assignment RHS uses its own value/coroutine context. The 24 refusal cases include own-scope transfer and suspension boundaries.

The new native ESM profile retains actual hoisted function declarations, native cyclic imports, live aliases and native assignment completion. Factories use `let` only for opted-in functions and initialize functions before a binding containing FunctionSet; existing function flags absent preserve old `const` factories and frozen bytes. Factory exports retain their existing snapshot semantics, not ESM live aliases.

The source suite adds 3 tests / 9 assertions. Both actual js/js-browser ESM CLI outputs execute in Node: 32 paired groups each, 64 total, covering pre-initialization back-edge reads/calls, nullish/falsy fallback, alias changes, saved function recursive reads, own declaration assignment, closure writes, RHS identity/once/throw behavior and actual namespace augmentation. The original Registry namespace IIFE and complete resolve body are pinned from the program emit, licensed and provenance hashed; its symbols identity is supplied by an explicit observation adapter. The Inject function body, control exports and two-module cycle are fixtures, not the actual Inject decorator or whole Registry/core lifecycle. Neither CLI target proves real browser/native/Q9 behavior or full stack/error-text parity.
