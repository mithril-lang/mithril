# Complete native YAML runtime source qualification

The 29 own Mithril modules derive from the entire pinned js-yaml 4.2.0 bundled
ESM source, SHA-256 `5b4536e72a2203aa6f159630caeefde35a95d8f95620f5a1d3c48efe3a0e76fa`.
The original archive and license are retained in `test/fixtures/native-esm-namespaces`.
This is operator-authored source, not a System One generation or performance claim.

All original module initializer ordering and private CommonJS cache closures are
represented as checked inert native source. Owner-scoped var declarations allocate
undefined bindings before ordered assignments; source block functions retain their
original lexical scope. Native function names and arity are preserved. Lexical
binding alpha-renaming and immutable primitive literal sharing keep source bounds.
The 44 private Loader functions are grouped in three own Mithril modules, returning
native functions that read getter-backed captures of the original wrapper bindings.
No original runtime body, JavaScript parser, TypeScript compiler, eval or Function
constructor is delegated to by the emitted runtime. The existing source, node and
package bounds remain unchanged.

The compile control checks deterministic artifacts, all 29 modules, the exact 15
original runtime exports and absence of external runtime dependencies. It invokes
both actual native ESM CLI targets in fresh owned directories and checks every
artifact byte before executing independent original-paired controls. The original
oracle is extracted only after archive and bundled-source hash checks. All 304
runtime groups must match: export aliases and metadata, all four schemas, scalar
kinds, anchors/merge/cycles, block/flow/Unicode/directives, invalid input and error
marks, multi-document/callback behavior, dump options, custom Type/Schema and
legacy safe* failure behavior. Both targets execute under Node.

The complete original public YAML type closure, UMD namespace behavior, actual
browser/native/Q9 and full Harness qualification remain pending. The 304 finite
groups are not an exhaustive equivalence proof. Include's 25-module source package
and YAML's 29-module package must be built separately under the unchanged 1 MiB
package source bound; integration uses the checked own artifact as a native package
import. The actual Include runtime and declaration CLIs also build a complete own YAML
package integration. It checks every runtime/declaration artifact byte, all 32
original-paired Include lifecycle/persistence groups, and all 6 positive/8 negative
original-paired strict Include type consumers per label. The full pinned original
YAML type facade is copied separately, retaining its CommonJS/UMD declaration mode
while runtime files are native ESM. Actual NodeNext package exports resolve the
default namespace and classes, with a strict positive and three exact-code
rejections, without skipLibCheck. These are the original type declarations;
they do not establish a native Mithril public YAML declaration closure. Branch and
current-main delivery remain required for the new source and integration.
