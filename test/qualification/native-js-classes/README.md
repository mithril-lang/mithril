# Native classes and disposal prerequisite

The checked native JS backend emits real ECMAScript classes from inert Mithril data. `NativeClass` has exactly name, extends, constructor and ordered members. A nil name is anonymous; nil extends omits heritage, while a Literal nil extends null. An optional constructor record has params/rest/body. Members are ordered field/method/get/set records with computed key expressions and a required boolean static flag. Methods use params/rest/body; fields use value. Getter has zero parameters, setter one, both have no rest. Fields/methods preserve native descriptors, initialization, name inference, nonconstructibility, subclassing and HomeObject behavior.

`HostSuperCall` takes value/spread items and is admitted only in a derived constructor or its lexical arrows. `HostSuperGet`, `HostSuperSet` and `HostSuperMethod` are admitted in member contexts, including field initializers and lexical arrows. Normal nested functions reset the context and cannot use super. Class methods/constructors admit own this/arguments/new.target; fields admit this/new.target, but arguments is refused even inside a lexical arrow. Computed keys and heritage use the enclosing lexical context. Native JavaScript enforces derived-constructor this-before-super, repeat-super, object/primitive return and extends-null behavior at runtime.

`HostUpdate` has exactly object/key/operator/prefix and emits a native property ++/-- expression. This preserves ToNumeric/BigInt, receiver/key single evaluation, getter/setter counts and prefix/postfix return value. It avoids replacing `++this.sn` with addition, which would change string and BigInt behavior.
